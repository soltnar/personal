# Версии

## 2.2.5 (2026-08-07)
- Объединены варианты одной точки: Октября 2, Жюль Верн/Ударник, Б. Покровская 59/63, Верхне-Печерская 14Б, Геологов 7А, Циолковского 19А и другие адресные дубли.
- Техническое название `Основной зал` больше не создаёт отдельный ресторан: точка определяется по адресу проходной.
- Фабрика на Белинского сохраняется отдельным производственным подразделением.

## 2.2.4 (2026-08-07)
- Сайт ждёт отдельный справочник сотрудников до 60 секунд, поэтому обычный ответ Saby за 15–25 секунд больше не теряется.
- Если справочник временно недоступен, ресторан определяется по `LocationInfo.LocationName` из события проходной.
- Для зависшей страницы справочника добавлена повторная попытка; дневной кэш пересобирается в формате 3 с названиями точек.

## 2.2.3 (2026-08-07)
- Автоматическая загрузка выручки всегда использует весь период из полей «С даты» и «По дату».
- Новый период проходной выбирается целиком и больше не наследует даты предыдущего недельного расчёта.
- Устранён преждевременный запрос выручки по старому выбранному диапазону.

## 2.2.2 (2026-08-07)
- Недостающие даты проходной загружаются пакетами до 7 дней одним отчётом Saby и затем сохраняются в дневной кэш.
- Официальный список сотрудников загружается отдельным параллельным запросом и больше не задерживает опрос кэша на 20 секунд; при медленном ответе расчёт использует должности и подразделения проходной.
- Для стабильности справочник сотрудников запрашивается страницами по 100 записей.

## 2.2.1 (2026-08-07)
- Возвращено распределение сотрудников по официальным подразделениям из `СБИС.СписокСотрудников`.
- Дневной кэш учитывает рабочие сутки целиком: с 04:00 до 03:59 следующего дня.
- Финальный ответ API больше не теряет список сотрудников после ожидания заполнения кэша.

## 2.2.0 (2026-08-06)
- Проходная сохраняется в Supabase отдельно по каждому дню и повторно используется без нового обращения к Saby.
- Недостающие даты загружаются последовательно в фоне, поэтому один тайм-аут больше не сбрасывает готовые дни всего периода.
- На странице отображается прогресс заполнения дневного кэша; повторный расчет готового периода выполняется сразу.
- Отдельный API списка сотрудников не используется: ресторан и должность определяются по данным проходной.
- Ежедневно после 05:00 автоматически перепроверяются предыдущие 5 дней, чтобы восстановить данные после временных сбоев Saby или интернета.

## 2.1.4 (2026-08-06)
- Автоматическая загрузка больше не запрашивает отдельный справочник сотрудников: ФИО, должность и подразделение берутся непосредственно из событий проходной.
- Временные ошибки `СБИС.СписокСотрудников` больше не могут замедлить или остановить загрузку проходной.
- Период сразу запрашивается частями по 4 дня: это исключает длительное ожидание большого запроса перед автоматическим повтором.
- Excel со списком сотрудников сохранён как ручной резервный способ переопределить ресторан.

## 2.1.3 (2026-08-06)
- Фильтры складов стали независимыми переключателями: можно одновременно выбрать кухню, бар и один склад, а повторным нажатием снять вариант.
- Страница официального списка сотрудников уменьшена до 100 записей для стабильного ответа Saby.
- Временная ошибка справочника сотрудников больше не блокирует проходную: используются кэшированные сотрудники или данные должностей из проходной.

## 2.1.2 (2026-08-05)
- При временном тайм-ауте Saby проблемный отрезок автоматически делится пополам до одного дня, а не прерывает весь расчёт.
- Получение официального списка сотрудников теперь повторяется один раз при временной ошибке и сообщает страницу сбоя.

## 2.1.1 (2026-08-05)
- Длинные периоды проходной загружаются частями по 10 дней с отображением прогресса, чтобы не превышать лимит Saby и Edge Function.
- Данные всех частей объединяются до расчета, поэтому результат сохраняет полный выбранный период.

## 2.1.0 (2026-08-04)
- Должности и подразделения переведены на официальный метод `СБИС.СписокСотрудников`.
- Внутренний отчет Saby теперь используется только для времени входов и выходов через проходную.
- Официальный список сотрудников кэшируется на 10 минут, чтобы не замедлять повторные расчеты.
- Для исторического периода учитываются даты приема и увольнения из официального справочника.

## 2.0.3 (2026-08-04)
- Устранена ошибка `Signal timed out`: Saby ограничивает параллельные запросы отчета, поэтому страницы по 1000 записей теперь загружаются последовательно.
- Для отдельно зависшей страницы добавлена одна автоматическая повторная попытка.

## 2.0.2 (2026-08-04)
- Устранен тайм-аут `546`: события проходной запрашиваются страницами по 1000 записей и до четырех страниц параллельно.
- Добавлены ограничение времени зависшего запроса и диагностические данные о длительности загрузки.
- Фильтры переработаны: рестораны получили отдельный крупный список, склады — компактный переключатель, должности — аккуратные карточки.

## 2.0.1 (2026-08-04)
- Убран видимый мультивыбор дат: период теперь задается только полями `С даты` и `По дату` в блоке автоматической загрузки.
- Все даты выбранного периода по-прежнему автоматически участвуют в расчете и Excel-матрице.

## 2.0.0 (2026-08-04)
- Добавлена автоматическая загрузка событий проходной, должностей и подразделений сотрудников напрямую из Saby через защищенную Supabase Edge Function.
- Период данных выбирается на сайте; события после полуночи до 04:00 по-прежнему относятся к предыдущему операционному дню.
- После загрузки проходной сайт автоматически подтягивает выручку за тот же период и сразу рассчитывает смены.
- Ручная загрузка трех Excel-файлов перенесена в закрытый резервный блок вместе с инструкцией.
