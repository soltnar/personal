# Ежедневные сводки кухни

Добавлено 27.10.2026. Сервер: personnel-notify. Настройки владельца: «Настройки → Telegram — ежедневная сводка шефам». Время по умолчанию — 10:00 МСК, за предыдущие календарные сутки.

Используется существующий @ilgp_bot из проекта «Выручка по ресторанам». Его токен скопирован серверным запросом из закрытого .env.bot в закрытую personnel_telegram_config; токен не выводился и не сохранён в исходниках. TELEGRAM_BOT_TOKEN в Edge Secrets имеет приоритет. Процесс бота выручки, его getUpdates, команды, PDF и действующее расписание не изменялись. Новый сервер вызывает только sendMessage.

Получатели пока не назначены. Каждый получатель привязан к одному предприятию, kitchen; список содержит 18 предприятий без фабрики. Новые назначения по умолчанию выключены. В сообщении: выручка кухни (или согласованный единый склад), учитываемые смены, выручка на смену, ФИО и reviewReason. Однонаправленные отметки с нулевой сменой теперь остаются в проверке и сообщении; суммы смен не менялись. Другие роли и unclassified в рассылку не попадают.

Если проходная не ready, отправка блокируется. Отсутствующая выручка явно помечается; выработка не вычисляется. Неоднозначная точка/отсутствие строки предприятия блокирует сообщение этой точки. Сообщения длиннее 4000 символов блокируются без обрезки ФИО.

Таблицы recipients, log, config закрыты RLS, права anon/authenticated отозваны. Доступ к API — только подтверждённому владельцу через Google; cron проверяет SHA-256 существующего attendance_cron_key. Конфигурация API возвращает только признак подключения, не токен.

Атомарная запись отправки с уникальностью recipient/date и enterprise/chat/date не позволяет параллельным вызовам отправить дубль. При неизвестном результате отправки запись сохраняется как review (или sending при аварийном завершении); автоматического повтора нет. После проверки Telegram владелец может обратиться к администратору для ручного снятия блокировки. За один вызов — до трёх сообщений; оставшиеся обрабатываются следующим вызовом.

## Состояние расписания

Автоматическая проверка отклонила создание cron personnel-telegram-daily из-за отсутствия согласованных конкретных получателей и привязок предприятий для отправки финансовых данных и ФИО. Cron НЕ создан. Не включать через обходной механизм. Требуется согласование получателей и явное разрешение включить расписание. План: */10 4-17 * * * UTC (07:00–20:50 МСК), каждое назначение ждёт своего send_hour и готовности проходной. При новом подключении в середине дня включённый получатель получит вчерашний отчёт на ближайшем запуске после своего часа.

## Пользовательские разделы — версия 5.0.19

Настройки теперь сгруппированы по пользователю (уникальный Telegram chat_id). Поле assignments хранит список предприятий и выбранных разделов для каждого: kitchen, hall, bar, delivery, operators. Операторы доступны у Коминтерна 166 CALL CENTRE; зал у этой точки не выбирается. Можно назначить пользователю несколько предприятий и несколько разделов одного предприятия. Старые назначения мигрируют в kitchen своего предприятия.

Каждое предприятие отправляется отдельным сообщением с выбранными разделами. Бар использует barRevenue, зал — hallRevenue (выручку без доставки), операторы — operatorsRevenue (сумму заказов сети с самовывозом) и operatorsOrders. Для зала, доставки и операторов загружается та же готовая история заказов, что и в приложении. Ошибка истории блокирует эти сообщения; независимые сообщения кухни/бара продолжают формироваться. ФИО ограничены выбранными ролями через restrictRows. Общая выручка и unclassified не раскрываются дополнительно.

Защита от повторов действует по пользователю, предприятию и дню. Уже отправленные предприятия не повторяются после возобновления пачки; до трёх сообщений за один вызов, ручная отправка сообщает об остатке. Отсутствие данных одной точки не препятствует проверке других точек.

Настройка, просмотр журнала, предпросмотр и ручная отправка по-прежнему разрешены только владельцу с подтверждённым Google email. Проверки HTTP 403 выполнены для постороннего пользователя на всех четырёх действиях. RLS и запрет прямого доступа anon/authenticated сохранены. Разрешения получателей приложения автоматически не расширяются.

Автоматическое расписание не включалось, реальные пользователи не добавлялись, сообщения не отправлялись.
