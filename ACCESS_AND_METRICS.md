# Выработка и права доступа

Выработка измеряется в рублях на учитываемую смену (1 или 0,5), а не на уникального человека за период. Кухня: выручка складов кухни / смены кухни. Бар: выручка складов бара / смены бара. Зал и доставка: вся выручка предприятия / смены соответствующей роли. Группа «Зал» включает существующую классификацию кассиров, менеджеров, мойщиков и официантов.

Исключение, согласованное владельцем: для Кварца (бывший Геологов), Моторного 2/1 и Коминтерна 166 кухня использует выручку единого склада, если нет отдельной строки склада кухни. В интерфейсе такой числитель подписан «Выручка единого склада». Для бара выручка единого склада не используется.

Сводка = сумма числителей / сумма смен за сопоставимые предприятие-дни: выручка раздела известна и смены больше нуля. Не усреднять дневные коэффициенты. При пропусках исключать одновременно выручку и смены этого предприятие-дня; показывать число исключённых предприятие-дней и смен, а показатель отмечать звёздочкой. Для фабрики без продаж выработка не определена; её смены не входят в знаменатель выработки ресторанов. Если сопоставимых смен нет — прочерк. CSV/Excel используют ту же выборку и включают охват.

Раскрытие предприятия за период сгруппировано по датам. Предупреждение предприятия учитывает только выбранные роли и показывает число проблемных записей. Причины видны возле соответствующих сотрудников.

Новый endpoint `personnel-report` проверяет сессию Supabase Auth и подтверждённый email. Администратор — существующий владелец soltnar@gmail.com. Другие пользователи получают только пары предприятие/роль из `personnel_access`. Без назначений — 403. Роли: kitchen, hall, bar, delivery. У каждой точки свой список ролей.

Таблица закрыта от anon и authenticated, RLS включён; управление только через серверный API администратора. Для назначения: открыть отчёт владельцем → «Права доступа сотрудников», указать Google email, предприятие и разделы. Пустой список ролей в POST удаляет назначение. Список не выдаётся сотруднику.

Данные проходной сначала объединяются по сотруднику и рабочим суткам, определяется последняя точка выхода (либо единственная точка при отсутствии выхода), после этого сервер применяет права. Иначе переходы между точками нарушили бы расчёт. Сырые события в ответ нового API не выдаются. Детали сотрудников ограничены разрешёнными разделами.

Кухня получает только выручку кухни, бар — только бара. Зал и доставка получают общую выручку, поскольку она нужна для их формулы. Это следует учитывать при назначении роли. Экспорт использует тот же ограниченный набор данных. Отзыв действует на следующий запрос; уже просмотренные или выгруженные данные отозвать невозможно.

Назначения не создаются автоматически. Авторизация в других приложениях сети регулируется независимо; новые права не отменяют ранее предоставленный доступ к отдельному приложению выручки.

PWA кеширует только публичные файлы интерфейса. Данные отчёта и вход требуют интернета; API-ответы и токены не сохраняются service worker. На iPhone установка: Safari → Поделиться → На экран Домой.

## Вход через Saby (4.1.0)

Владелец входит через Google и открывает «Вход Saby и пользователи». В Saby нужно зарегистрировать интерактивное внешнее приложение с адресом возврата `https://soltnar.github.io/personal/saby-callback.html`, затем сохранить его client_id и client_secret в настройках. Секрет не передаётся в исходники и не возвращается интерфейсу; хранится в закрытой серверной таблице. Не используйте сервисные учётные данные вместо интерактивного приложения.

После первого входа пользователь появится в списке ожидания. Владелец разрешает вход и назначает предприятия и разделы; без обоих действий отчёт недоступен. Идентификатор — пара аккаунт Saby + пользователь, email не даёт автоматических прав. Google-вход владельца сохраняется.

OAuth использует одноразовый code, state и привязку к секрету текущего браузера, срок заявки 5 минут. Токен Saby используется только сервером для получения профиля и не сохраняется. Собственная сессия приложения действует 8 часов, в базе хранится только её SHA-256. При блокировке сессии удаляются, права проверяются заново при каждом запросе. Таблицы авторизации закрыты RLS и недоступны anon/authenticated; API самостоятельно проверяет Google или сессию Saby. Callback требует того же HTTPS origin, поэтому локальный file:// не подходит для реального OAuth.

Проверки: `tools/test-saby-auth.mjs` и `tools/test-personnel-report.mjs`. Реальный OAuth требует зарегистрированных реквизитов Saby и отдельного сквозного тестирования после настройки.

## Рабочее пространство (4.2.0)

Боковое меню разделяет обзор, подробный отчёт, проверку данных, настройки и управление пользователями. Период и фильтры общие для трёх аналитических экранов; переходы не перезагружают данные. Профиль открывается по имени в шапке или внизу меню: показывает способ входа, имя и доступную выборку текущего отчёта (это не полный реестр назначений). Владельцу через Google доступен раздел пользователей; серверные проверки прав не изменены.

На узком экране меню открывается кнопкой, закрывается выбором раздела или Escape; фон становится недоступным для фокуса. `tools/test-workspace.mjs` проверяет профили Google/Saby, владельца и гостя, закрытие административных экранов и очистку данных при смене аккаунта.

## Автоматическая загрузка (4.2.2)

Планировщик после 05:00 МСК заполняет отсутствующие и неуспешные даты от начала сохранённой истории до вчерашнего дня. Готовые дни пропускаются, даже если сохранены давно. За один запуск загружается один день; после ошибки дата повторяется не раньше следующего московского календарного дня. Утреннее расписание запускается каждые 10 минут с 05:00 до 06:50 МСК, то есть обрабатывает до 12 дней за утро. Остаток очереди продолжится следующим утром. Сервисное имя cron-задания исторически содержит `last-5-days`, но пятидневное ограничение больше не применяется.

Принудительное обновление остаётся отдельным действием владельца. Ошибка загрузки не отправляет `rows: []` в базу; при неудачном ручном обновлении прежнего готового дня восстанавливаются статус готовности и исходное время сохранения. Проверки: `tools/test-attendance-schedule.mjs`, включая выполнение обработчика с имитацией ошибки Saby.
